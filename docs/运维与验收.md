# 运维与验收说明

本说明记录当前项目的实际维护方法及可核验结果。未执行的项目明确保留为待验证，不以页面可见或编译成功替代业务正确性。

## 一、数据库维护边界

- 唯一业务数据库引擎为 SQLite，源文件为项目根目录 `db.sqlite3`。
- 结构由 `scheduling/models.py` 与 Django migrations 管理，禁止在 Navicat 手工建表、删表、重命名字段来“同步模型”。
- 排班发布、床位责任、申请审核及患者信息均通过业务接口修改。数据库直接写入会绕过权限、版本与审计。
- 不删除或重置历史迁移；不覆盖源数据库来重新演示；不提交数据库、备份、Navicat连接资料或真实患者信息。

执行结构变更前，在项目根目录完成：

```bash
source .venv/bin/activate
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py showmigrations scheduling
python scripts/backup_database.py
python manage.py migrate --plan
```

如果模型确有待迁移变更，应先生成和审查该迁移的字段默认值、约束与数据影响，再执行 `python manage.py migrate`。`makemigrations --check --dry-run` 非零退出应先调查，不能以删迁移解决。

## 二、SQLite一致性备份与隔离恢复

常规命令：

```bash
source .venv/bin/activate
python scripts/backup_database.py
```

指定新的备份目标时：

```bash
python scripts/backup_database.py --source db.sqlite3 --output backups/icu-manual-new.sqlite3
```

目标文件必须不存在。脚本使用只读源连接及 SQLite backup API，适合对正在运行的开发库取得一致性快照；随后在隔离临时目录恢复，核验数据库完整性和每张表的记录数，最后移除临时恢复库。备份文件保留在 `backups/`，权限为 `0600`。

若只需要复验一个已经存在的备份，不创建新业务库：

```bash
source .venv/bin/activate
python -c "from scripts.backup_database import verify_restore; print(verify_restore('backups/icu-manual-new.sqlite3'))"
```

`integrity: ok` 及逐表计数一致说明该次备份可被恢复为结构一致的 SQLite 文件；它不证明临床记录内容正确，也不证明系统级灾难恢复、密钥恢复或全部应用行为已经验证。

### 实际恢复业务服务的受控流程

本轮只执行了隔离恢复检查，没有替换源库。若将来需要实际恢复，应在维护窗口完成：

1. 确认环境、恢复原因、目标版本与负责人；停止所有对该数据库的写入服务和数据库客户端。
2. 对当前数据库再做一次带时间戳的一致性备份，保留恢复前状态及审计材料。
3. 将待恢复备份先在独立目录验证，核对所配套的代码版本、迁移版本、关键发布快照和账号权限。
4. 采用明确的恢复工单处理数据库及相关SQLite侧文件，不直接覆盖运行中的文件；保持文件所有者和最小访问权限。
5. 用匹配代码启动隔离验证环境，执行检查、只读数据核对及合成数据流程测试；确认后才恢复正式访问。
6. 记录恢复人、时间、来源、目标、结果及业务补录安排。按医院要求保存备份、验证证据并落实访问与销毁策略。

本项目未自动执行上述正式恢复流程，不提供一条无提示覆盖业务库的命令。

## 三、Navicat只读核对

### 可用性记录

2026-10-26检查 `/Applications` 与用户 `~/Applications`，未发现 Navicat 应用。没有执行 Navicat GUI 连接、许可证/SQLite功能验证或数据查看。因此“Navicat可视化核对”仍待在安装且支持SQLite的环境完成。这里未以其他数据库客户端替代用户指定的 Navicat。

### 安装完成后的连接步骤

1. 使用支持 SQLite 的 Navicat 版本，在连接前确认是开发、测试还是正式环境。
2. 优先连接本轮生成的备份副本进行核对；如需读取开发源库，明确选择现有 `db.sqlite3`，不要选择“创建新数据库”。
3. 连接设置采用当前版本支持的只读方式；同时使用文件访问权限限制，避免误操作。记录源文件绝对路径和备份时间。
4. 展开 `scheduling_*` 业务表与 `django_migrations`，核对结构、索引、外键与记录；不要执行DDL或直接改业务内容。
5. 运行下面的只读查询。结果按实际业务变化记录，不机械要求永远等于初始化数据量。
6. 结束后关闭连接，避免长事务占用。截图或导出不得包含真实患者敏感信息、密码哈希或会话内容。

```sql
PRAGMA query_only = ON;
PRAGMA integrity_check;
PRAGMA foreign_key_check;

SELECT app, name, applied
FROM django_migrations
WHERE app = 'scheduling'
ORDER BY applied;

SELECT name, sql
FROM sqlite_master
WHERE type = 'table' AND name LIKE 'scheduling_%'
ORDER BY name;

SELECT COUNT(*) AS nurse_count FROM scheduling_nurse;
SELECT COUNT(*) AS bed_count FROM scheduling_bed;
SELECT COUNT(*) AS active_patient_count
FROM scheduling_patient WHERE bed_id IS NOT NULL;

SELECT id, group_id, start_date, draft_id, draft_revision, published_by_id, created_at
FROM scheduling_schedulepublication ORDER BY id DESC LIMIT 20;

SELECT id, group_id, date, shift, draft_id, draft_revision, published_by_id, created_at
FROM scheduling_bedpublication ORDER BY id DESC LIMIT 20;
```

`PRAGMA query_only` 只约束当前连接，并非账户级权限体系；不能替代文件权限和操作审批。正式库不得用Navicat绕过Django进行人员责任分配、患者变更、审批或发布修复。

## 四、自动化与业务验收

下面是应执行的验收项，状态必须以对应命令或浏览器实际结果为准；本节没有把尚未回报的测试统一标记为通过。

| 验收项 | 方法与检查内容 |
| --- | --- |
| Django系统检查 | `python manage.py check` |
| 后端测试 | `python manage.py test`；隔离测试数据库中的业务、接口、权限、版本及约束场景 |
| 模型迁移一致性 | `python manage.py makemigrations --check --dry-run` |
| Python依赖 | `python -m pip check` |
| Vue生产构建 | `cd frontend && npm run build` |
| 浏览器主流程 | `python scripts/run_browser_tests.py` 在临时数据库与独立服务中运行；登录→人员→排班生成/编辑/校验/发布→患者资料人工核对→分床/调整/发布→工作量明细。真实 AI 接口须另行配置与测试 |
| 版本与并发 | 同版本并行修改不得静默覆盖；重复发布同一版本不重复计数；返回冲突后刷新重试 |
| 统计一致性 | 草稿不计入；最新有效正式版本；夜班开始日一次；每日工时与个人环图相等；管床人数来自责任快照 |
| AI失败 | 无明确床号、重复/冲突床号、未人工核对、外部API超时或非法结构均不自动写入正式患者 |
| 床位安全 | 资格失效、人员不足、不合法三床、总负荷超限应阻断；合规三床需人工确认 |
| 角色限制 | 第3组管理本组、护士长只读、系统管理员全局、跨组拒绝；旧护士个人账号停用 |
| Navicat | 待有可用安装后按上述步骤核对 |

后端单元/接口测试通过与有限的并发冲突测试通过，不等于已测得生产高并发吞吐量。上线前需在目标硬件、预期数据量、并发读写和备份场景下进行持续压力测试，记录锁等待、冲突率、响应时间与恢复能力。

## 五、已知集成与部署边界

- 开发测试使用隔离的合成资料；真实医院人员与病例须经过授权导入和逐项核验。
- 真实大模型API在系统设置中由系统管理员配置，Key以密文保存在SQLite。已用隔离合成资料验证真实调用；连接结果不代表医学识别准确率，也不保证以后网络和供应商状态不变。
- 外部模型字段脱敏为基础过滤，不是经过认证的完整去标识系统；不要将真实数据直接用于开发联调。
- HIS/EMR、考勤未接入。统计来自最终排班与床位责任快照，不能称为实际出勤。
- 通知为站内记录；没有短信、邮件或第三方消息推送。
- 工作台采用保存后刷新与15秒可见页定时刷新。客户端缓存不作为最终权限或安全判定依据。
- `.env` 中正式密钥、域名、HTTPS、Cookie、反向代理、静态资源和备份策略需在医院部署时配置；开发服务器不是生产托管方案。
- 负荷权重、年资和班次人数阈值仍需医院护理管理方签署；设置中的认证字段不能替代线下审批。
- 备份文件权限不能替代磁盘/备份加密、远端备份与定期恢复演练。
- SQLite备份不包含 `private_uploads/avatars/` 的私有头像文件，也不包含 `~/.local/share/icu-scheduler/ai-master.key` 或外部主密钥环境变量；需分别安全备份并验证配套恢复。
