# 分组床位配置

在“系统设置 → 病区基础设置”中，输入起始床位号和数量后点击“生成编号”，可形成连续候选床位；也可添加不连续的数字床号或由英文字母、数字、连字符、下划线组成的自定义床号（例如 `101A`、`ICU-1`）。数字床号为 1–999999，每组最多配置 500 张。输入的字母统一转为大写，数字前导零不作为不同床号。

候选列表中的床号按钮控制**显示**，旁边的开关控制**实际开放状态**。新建床位默认未开放，需逐床确认。可全选或取消全选显示；点击“移出”只移出本组当前配置，不删除记录，也不改变开放状态。保存前显示新增、移出、状态变化和阻断原因；确认保存时后端在事务中再次检查权限、数据版本和安全状态。

系统分别维护配置范围、工作台显示、实际开放和患者占用。开放床位统计包括仍物理开放但未列入当前配置的床位；工作台卡片显示本组已配置并选中显示的床位。当存在未设置显示的开放床位时，工作台提示其数量，避免把显示范围误认为实际开放范围。若旧数据存在已隐藏或未配置却有患者的床位，工作台仍强制展示，智能分床会阻断并要求处理。对于有在床患者、当前或未来分床草稿责任或有效正式责任的床位，不能隐藏、关闭或移出配置。床位范围变更不重编号既有床位，现有床位通过稳定 ID 复用，已发布排班和分床快照不被修改。床位配置发生变化会使相关分床草稿需要重新校验。

当前系统使用大组设置中的 `ward_code` 判定同一病区，未经用户要求未另建病区表或共享床位机制。同一病区中其他大组已有的床号不能新增或重新纳入本组；更改病区编号前也检查已有床位冲突。此判定依赖管理员为同一实际病区使用一致的病区编号，系统无法识别不同编号其实代表同一实际病区；历史上已存在的冲突不会由迁移擅自删除。当前模型不支持跨组共享同一物理床位或直接更正既有物理床号，这些操作应先完成独立的权限、数据映射和审计设计。

迁移 `0020` 保留床位及患者主键，将原数字床号转换成可表示自定义编号的文本；原来开放的床位保持配置和显示，原来不开放的床位保留原记录并保持不显示。迁移根据已有开放床号初始化本组起始号，不根据组号推断。该迁移在引入非数字床号后不可无损自动逆向；应通过经过验证的 SQLite 备份执行恢复，不能直接回滚覆盖运行中的数据库。

床位配置接口使用 `beds/configure-preview/` 预览和 `beds/configure/` 确认保存；均使用现有登录身份、组范围及版本检查。总览和分床仍根据数据库中的实际开放及患者状态统计，不使用前端显示列表替代真实患者集合。当班护士仍来自对应日期和班次的有效正式排班。
